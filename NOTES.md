Agent nhiều khả năng sẽ validate body trước rồi mới tra `Idempotency-Key` (hoặc check key rồi insert theo kiểu check-then-insert không atomic), trong khi spec yêu cầu thứ tự cố định: key → JSON → **tra key (replay / reused / in-flight)** → validation → unknown item. Lý do: thứ tự này ngược với trực giác “validate trước”, và `409 in-flight` cần một cơ chế claim key atomic riêng, trong khi spec lại chỉ cho lưu key cùng transaction với order và chỉ lưu khi `201`, nên agent thường bỏ sót hoặc làm race.
2. Agent nhiều khả năng sẽ trả `nextCursor` khác `null` bất cứ khi nào trang đầy `limit` item, nên client có thể nhận cursor dẫn tới trang rỗng, vi phạm “`null` if and only if không còn order nào”. Lý do: cách đơn giản nhất là `LIMIT limit`, còn cách đúng (fetch `limit + 1` rồi cắt bớt) đòi hỏi agent đọc kỹ một câu nằm giữa phần mô tả cursor.
